================================================================================
## PROJECT OVERVIEW
================================================================================

This is a full-stack Circular Economy Marketplace platform that connects surplus 
material owners with seekers, enabling material reuse and reducing environmental 
waste. The platform features real-time geospatial search, AI-powered suggestions, 
logistics coordination, and sustainability impact tracking.

### Tech Stack

**Backend:**
- Node.js + Express.js
- MongoDB with Mongoose ODM
- JWT Authentication (access + refresh tokens)
- GeoJSON for location-based queries (2dsphere indexes)
- Port: 5001

**Frontend:**
- React 19 + TypeScript
- Vite + TailwindCSS v4
- Redux Toolkit for state management
- React Router v7
- Framer Motion for animations
- Leaflet + React-Leaflet for maps
- Port: 5173 (dev)

### Project Structure

```
root/
├── backend/
│   ├── index.js              # Express server entry point
│   ├── config/Db.js          # MongoDB connection
│   ├── controllers/          # Route handlers

│   ├── routes/               # API route definitions
│   ├── middleware/           # Auth, validation middleware
│   └── utils/                # Helper functions, token generation
│
├── frontend/
│   ├── src/
│   │   ├── api/              # API client and service functions
│   │   ├── components/       # Reusable UI components
│   │   ├── config/           # Constants, routes, API endpoints
│   │   ├── hooks/            # Custom React hooks
│   │   ├── layouts/          # Page layouts (Dashboard, Auth)
│   │   ├── pages/            # Page components
│   │   ├── store/            # Redux store and slices
│   │   ├── routes/           # Route guards (ProtectedRoute)
│   │   └── types/            # TypeScript interfaces
│   └── ...
```

## DATA MODELS

### User Model
```javascript
{
  _id: ObjectId,
  email: String (unique, lowercase),
  password: String (hashed, select: false),
  name: String (required),
  phone: String,
  avatar: String (url),
  role: "buyer" | "seller" | "ngo" | "logistics_partner" | "admin",
  location: {
    type: "Point",
    coordinates: [Number, Number]  // [longitude, latitude]
  },
  address: {
    street: String,
    city: String,
    state: String,
    pincode: String,
    country: String (default: "India")
  },
  isEmailVerified: Boolean,
  isPhoneVerified: Boolean,
  isActive: Boolean,
  isBanned: Boolean,
  businessDetails: {
    companyName: String,
    gstNumber: String,
    businessType: "manufacturer" | "retailer" | "wholesaler" | "recycler" | "other",
    website: String
  },
  impactStats: {
    totalListings: Number,
    totalTransactions: Number,
    weightDiverted: Number,    // kg
    co2Saved: Number           // kg
  },
  rating: {
    average: Number (0-5),
    count: Number
  },
  refreshToken: String (select: false),
  createdAt: Date,
  updatedAt: Date
}
```

## IMPORTANT NOTES FOR FRONTEND DEVELOPMENT
================================================================================

### 1. Coordinates Format
- **MongoDB/Backend:** [longitude, latitude] - GeoJSON standard
- **Leaflet/Frontend:** [latitude, longitude] - Leaflet standard
- **ALWAYS CONVERT** when passing between systems

### 2. Authentication
- Store `accessToken` in localStorage for API requests
- Use `Authorization: Bearer <token>` header
- Refresh token flow: POST to /api/auth/refresh-token when 401 received
- User session can be restored via GET /api/auth/me

### 3. API Client Setup (Axios)
```typescript
// frontend/src/api/client.ts
const apiClient = axios.create({
  baseURL: "http://localhost:5001",
  headers: { "Content-Type": "application/json" }
});

apiClient.interceptors.request.use(config => {
  const token = localStorage.getItem("accessToken");
  if (token) config.headers.Authorization = `Bearer ${token}`;
  return config;
});
```

### 4. Standard API Response Format
```typescript
interface ApiResponse<T> {
  success: boolean;
  message?: string;
  data?: T;
}

// Paginated responses
interface PaginatedResponse<T> {
  success: boolean;
  data: {
    items: T[];
    pagination: {
      page: number;
      limit: number;
      total: number;
      totalPages: number;
    }
  }
}
```

### 5. User Roles
- **buyer**: Can browse marketplace, request materials, track requests
- **seller**: Can list materials, manage listings, respond to requests
- **ngo**: Similar to buyer, focus on donation materials
- **logistics_partner**: Manage deliveries and pickups
- **admin**: Full platform access

### 6. Material Status Flow
```
draft → available → reserved/partially_reserved → completed/expired/removed
```

### 7. Request Status Flow
```
pending → approved → (creates transaction) → completed
       → rejected
       → cancelled
       → expired (auto after 7 days)
```

### 8. Transaction Status Flow
```
initiated → scheduled → in_progress → handed_over → received → completed
                                   → disputed → resolved
         → cancelled
```

### 9. Key Environment Variables
```env
# Backend (.env)
PORT=5001
MONGODB_URI=mongodb://localhost:27017/circular_marketplace
JWT_SECRET=your_jwt_secret
JWT_REFRESH_SECRET=your_refresh_secret
OPENAI_API_KEY=your_openai_key

# Frontend (.env)
VITE_API_URL=http://localhost:5001
```

### 10. Image Handling
- Images are stored as URLs (can be Cloudinary, S3, or any CDN)
- Material images include `isPrimary` flag
- Fallback to category emoji if no image

### 11. Search
- Backend uses MongoDB text index on title, description, tags
- Full-text search via `search` query parameter
- Geospatial search via /api/materials/nearby endpoint
